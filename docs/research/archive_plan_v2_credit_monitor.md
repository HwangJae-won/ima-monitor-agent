# IMA·기업금융 심사역을 위한 기업 신용위험 모니터링 및 검토 지원 AI — 프로젝트 계획안 (v2)

## 0. 프로젝트 정의

- **한 줄 정의:** 공개 재무·공시·시장 데이터를 공시시점 기준으로 통합해, 향후 12개월 내 재무·신용 위험사건 가능성이 높은 기업을 검토 우선순위와 원문 근거와 함께 제시하고, 담당자의 처리 이력을 남기는 시스템
- **사용자:** IMA·기업금융 사후관리 담당자(심사역)
- **범위 문구:** 본 프로젝트는 실제 IMA 운용자산이 아닌 공개 데이터를 사용하며, 기업금융 사후관리 업무에 활용되는 상황을 가정한 검증입니다.
- **증명하려는 문장:** 동일한 검토 건수에서 기존 재무비율 경보보다 위험사건 기업을 더 많이, 더 일찍 찾아냈고, 담당자가 원문 근거를 확인하고 처리 이력을 남길 수 있도록 구현했습니다.

## 2. 분석 대상

### 학습 표본 / 시연 표본 분리
| 구분 | 목적 | 규모 | 선정 |
|---|---|---|---|
| 학습 표본 | 모델 학습·검증 | 사건 기업 100개 이상 목표, 전체 600~1,000개 | 모집단 기준 적용, 사건 기업 전부 포함 |
| 시연 표본 | 모니터링 목록 | 50~100개 | 심사역 등록 목록 가정 (비상장 2~3곳 포함) |

### 모집단 선정 기준
1. 비금융 상장기업
2. 업종·규모별 구성 확인
3. 기업금융 관련성: 회사채·CB·BW 발행 이력 또는 일정 규모 이상 차입금
4. 생존편향 방지: 각 시점 존재 기업 포함, 이후 상장폐지 기업 유지

### 상장폐지 기업 처리
- 한투 API 시세 미조회 시: 재무 기반 모델에는 포함, 시장 모델은 결측 처리 (마지막 조회 가능 시점까지 사용)
- 처리 방식 문서화

### 의사결정 기준
2주차 말 사건 기업 60개 미만 → 사건 정의 확장(자본잠식 30% 등) 또는 기간 확장 → 그래도 부족 시 모델 비교 축소, 업무 흐름 비중 확대

## 3. 예측 목표: 위험사건 정의

- 목표: 향후 12개월 내 사전 정의한 재무·신용 위험사건 발생 여부
- 점수 명칭: 위험사건 예측 점수 (부도확률 아님)

| 유형 | 사건 | 출처 | 처리 |
|---|---|---|---|
| A. 신용사건 | 회생절차 개시 신청, 채무불이행, 워크아웃 신청 | OpenDART 주요사항보고서 | 전부 포함 (핵심) |
| B. 회계·감사 위험 | 감사의견 한정·부적정·의견거절 | OpenDART 감사보고서 | 포함, 계속기업 불확실성 별도 표시 |
| C. 재무 부실 | 자본잠식률 50% 이상, 관리종목 지정 중 재무 사유 | KIND + 재무제표 | 사유 확인 후 포함 |
| 제외 | 비재무 사유 관리종목·상장폐지 (공시 위반, 주식분산, 횡령·배임은 별도 표시) | KIND | 학습 제외, 기준 기록 |

- 성능은 전체 + 유형별(A/B/C) 제시
- "신용등급보다 먼저 감지"는 가설로만. 기본 비교 대상은 재무비율 경보 규칙

## 5. 모델 실험 (4단계 비교)

| 단계 | 모델 | 질문 |
|---|---|---|
| 0 | 재무비율 규칙 (이자보상배율<1 연속 2년, 부채비율>300%, 영업CF 음수 등) | 기준선 |
| 1 | 재무 데이터 모델 (로지스틱 → 부스팅) | 재무지표 결합 효과? |
| 2 | 재무 + 시장 신호 | 탐지 시점을 앞당기는가? |
| 3 | 재무 + 시장 + 머튼 부도거리 | 추가 정보가 있는가? (없어도 보고) |

- 시장 신호: 20·60일 변동성, 최대 낙폭, 공매도·대차·신용 4주 변화율, 기관·외국인 연속 순매도 일수, 거래량 급증 횟수
- 부도거리: KMV식 반복 추정, 상대 순위 변수로만 사용, 가정·한계 명시

## 6. 검증 설계

### 규칙
1. 공시시점 기준(`available_from`)으로만 변수 생성
2. 시간순 검증 (예: 2019~2022 학습 → 2023 검증 → 2024 테스트), 학습 레이블은 검증 시작 전 관측 완료분만
3. 관측기간 12개월 미만 기업-시점은 정상 지정 금지, 제외 처리
4. 사건 공시일 이후 신호 제외 + 직전 N일(5영업일) 제외

### 지표
| 지표 | 의미 |
|---|---|
| 상위 K개 검토 기업 적중률 | 검토 시간 배분 |
| 위험사건 탐지율 (유형별) | 놓친 비율 |
| 기업당 연간 오경보 횟수 | 검토 부담 |
| 사전 탐지 기업 선행기간 중앙값 + 미탐지 비율 | 얼마나 먼저 (탐지 성공 기업만의 값임을 명시) |
| 동일 경보 건수에서 0단계 대비 개선폭 | 핵심 성과 지표 |

## 7. 업무 흐름

### 사용자 흐름
1. 모니터링 기업 목록 등록 (종목코드/DART 고유번호, 비상장 포함)
2. 재무·시장 데이터와 신규 공시 일 단위 갱신 (스케줄러)
3. 위험 점수와 변화량 기준 검토 우선순위 제시
4. 기업 클릭 → 이전 경보 대비 변화, 근거 지표, 공시 원문 링크
5. 추가 확인 / 관찰 유지 / 검토 완료 처리 + 메모, 이력 저장

### 리포트 구성
| 구성 | 내용 | 주체 |
|---|---|---|
| 관측 사실 | 지표 값, 변화량, 기준일 | 코드 계산, LLM 서술 |
| 모델 설명 | SHAP 기여 변수·방향 ("모델 점수 기여, 부실 원인 아님" 고정 문구) | 코드 + LLM |
| 공시 근거 | 공시 제목, 접수일, 원문 링크 | 코드 검색, LLM 요약 |
| 검토 항목 | 차입금 만기, 현금흐름, 자금조달 계획, 담보·보증 | LLM 제안 (템플릿 + 맞춤) |

### LLM 안전장치
- 숫자는 코드, LLM은 근거 ID 범위 내 정리만
- 인과 단정 표현 금지 → 출력 검증
- 근거 없음 / 데이터 기준일 경과 상태 표시
- 사용 근거 ID 저장 (추적 가능)

## 8. 시스템 구조

```
[수집]  OpenDART / KIND / 한투 API / ECOS  — 스케줄러, 재시도, 속도 조절, 증분 수집
[저장]  DuckDB 또는 PostgreSQL — raw / pit / labels / workflow
[분석]  변수 생성 → 4단계 모델 → 시간순 검증 → SHAP
[서비스] FastAPI (점수, 경보, 처리 이력), LLM 리포트 생성기 (근거 ID 기반, 출력 검증)
[화면]  Streamlit — 우선순위 목록 / 기업 상세 / 처리 이력
```

보안·운영: 한투 API 조회 전용(주문 모듈 미포함), 키 `.env` 분리, 토큰 캐싱, 호출 로그.

### 면접 예상 질문
- 코스닥 예측이 IMA 운용에 어떻게 도움? → 공개 데이터로 사후관리 업무 흐름과 검증 방법을 구축, 내부 자료 연결 시 공통 기반 유지·시장 계층 조건부 작동

- LLM 오류? → 근거 ID 범위 제한, 출력 검증, 근거 없음 표시
