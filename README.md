# KIS API·DART 기반 기업금융 사후 모니터링 조사 Agent

> 한국투자증권의 IMA(종합투자계좌) 사업을 공부하다가, 기업에 자금을 공급한 뒤 **회수 가능성을 계속 확인하는 업무**에 관심이 생겼습니다.
> 그 업무를 이해하려고, 공개 자료(DART 공시·재무제표, KIS Open API 시세·수급)만으로
> "투자한 기업의 상태가 달라졌는지, 달라졌다면 무엇을 더 확인해야 하는지"를 조사하는 Agent 를 만들었습니다.

**이 프로젝트는 실제 IMA 편입 자산이 아니라 공개 상장기업을 대상으로 한 업무 시뮬레이션입니다.**
내부 여신·상환 자료는 없으므로, 공개 자료로 판단할 수 있는 것과 없는 것을 구분해 "추가 확인 사항"으로 남기는 데 집중했습니다.

---

## 왜 이 업무인가

| 단계 | 내용 |
|---|---|
| 사업을 봤다 | 한국투자증권은 2026년 경영 키워드로 자본·국경·업의 경계를 넘는다는 'Beyond Boundaries' 를 내걸었고, 그중 자본의 경계에서 IMA 를 신규 수익원으로 꼽으며 "철저한 리스크 관리"를 함께 강조했습니다. IMA 는 고객 수탁금을 기업금융 관련 자산에 70% 이상 운용해야 하고, 고객에게 만기 원금 지급 의무가 있습니다. [원문 확인: docs/business_notes.md] |
| 업무를 좁혔다 | 자금을 모으는 일, 투자 대상을 고르는 심사, 그리고 **투자 이후 상태 변화를 지켜보는 사후관리**가 다릅니다. 이 프로젝트는 세 번째만 다룹니다. |
| 판단을 배웠다 | 주가가 떨어지는 것과 빚을 못 갚게 되는 것은 다른 일입니다. 담당자는 영업현금흐름·차입금 만기·현금·자금조달 공시로 상환능력을 보고, 주가·수급은 "확인할 이유"로 씁니다. 자금조달 '결정' 공시는 계획일 뿐, 납입·발행실적 공시가 있어야 조달이 끝난 것입니다. |
| 직접 만들었다 | 이 판단 기준을 코드와 Agent 의 조사 규칙으로 옮겼습니다. 숫자는 코드가 계산하고, Agent 는 근거를 찾아 다니며, 검증 코드가 Agent 의 메모를 도구 결과와 대조합니다. |

디지털 조직 관점에서 보면 이것은 **현업(기업금융·리스크) 담당자를 위한 AI 어시스턴트**의 한 사례입니다.
한국투자증권이 '금융 라이선스를 가진 테크 기업'을 내걸고 본부별 AI 활용을 추진하는 방향과 닿아 있다고 봤습니다.

## Agent 가 하는 일

```
[코드]  기준일 시점의 재무 스냅샷(DART) + 시장 신호(KIS) → 변화 신호 탐지
          └ 상환능력 신호: OCF 음수·급감, 단기차입금 증가, 이자보상배율<1, 현금<단기차입금 절반, 자본잠식 …
          └ 시장 신호   : 20일 -20%, 60일 낙폭, 거래량 급증, 신용잔고 급증, 공매도 비중 급증, 지속 순매도
[Agent] 신호를 보고 "무엇을 더 확인할지" 결정 → 도구 호출 (최대 6회, 경로는 중간 결과에 따라 달라짐)
          ├ get_disclosures(category=funding|credit_event|audit|…)   DART 공시·주요사항보고서
          ├ check_funding_completion(since)                          발행'결정' → 납입·발행실적 '완료' 추적
          ├ get_financial_snapshot(asof=과거)                         전기 대비 맥락
          └ get_market_signals(lookback_days)                        KIS 시세·신용·공매도·수급 재조회
[Agent] 메모 작성: 관측된 변화 / 상환능력 근거 / 시장 신호 / 종합 검토(일치·엇갈림·부족) / 추가 확인 사항
[코드]  검증: 인용한 근거 id 가 실제 수집됐는가, 메모의 숫자가 도구 결과에 있는가, 시장 신호를 상환능력의 증거로 단정했는가,
         '조달 완료' 표현에 실적 공시 근거가 있는가
```

세 가지 설계 원칙
1. **기준일(as-of) 고정** — 모든 도구는 기준일 이전에 *접수된* 자료만 반환합니다(DART 접수일, KIS 영업일). 과거 시점으로 돌리면 "그때 공개돼 있던 것만으로 무엇이 보였나"를 정직하게 복기할 수 있습니다.
2. **숫자는 코드, 판단 보조는 LLM** — 지표 계산·변화 탐지는 전부 코드입니다. LLM 은 계산하지 않고 근거 id 로만 인용합니다.
3. **확인 불가를 남긴다** — 차입금 만기 일정, 약정 위반, 담보 가치처럼 공개 자료로 알 수 없는 것은 결론 대신 "필요 자료"와 함께 추가 확인 항목으로 남깁니다.

## 평가 방법

보고서 품질이 아니라 **조사 행동**을 봅니다. 같은 기업·기준일에 대해 도구 없이 자료를 한 번에 주고 쓰게 한 대조군(`scripts/baseline.py`)과 나란히 놓고, 다섯 항목을 사람이 채점합니다.

| 항목 | 확인 방법 |
|---|---|
| 필요한 공시를 찾아냈는가 | 사례별 "찾았어야 할 공시" 목록과 trace 대조 |
| 차환·증자 계획을 조달 완료로 오해하지 않았는가 | `check_funding_completion` 호출 여부와 메모 표현 |
| 주가 하락을 상환능력 악화로 단정하지 않았는가 | 종합 검토 문장, 자동 검증 경고 |
| 근거가 부족할 때 추가 조회하거나 보류했는가 | open_items 의 질과 trace |
| 도구 없는 요약보다 나은가 | 대조군과 누락·오류 비교 |

## 실행

```bash
cp .env.example .env          # KIS 앱키(조회 전용), OpenDART 키, LLM 키
pip install -r requirements.txt
python -m pytest              # 네트워크 없이 도구·검증 규칙 테스트

python scripts/build_universe.py --months 18                 # 채권·CB 로 조달한 비금융 상장사 후보
python scripts/run_monitor.py --code 000000 --asof 20251015   # 기업 1곳 조사 메모
python scripts/run_case.py --code 000000 --dates 20240630,20240930,20241231,20250331   # 사례 복기
python scripts/baseline.py --code 000000 --asof 20251015      # 대조군(도구 없음)
```

보안: KIS API 는 **조회 전용**이며 주문·정정·취소 모듈이 코드에 없습니다. 키는 `.env` 에만 두고, 접근토큰은 발급 제한(1분 1회)을 지키기 위해 디스크에 캐시합니다. API 응답 캐시에는 키·토큰이 포함되지 않습니다.

## 정직한 범위

- 대상은 **공개 상장기업**이며, "IMA 가 투자할 법한 기업군(채권·CB 로 조달한 비금융 상장사)"이라는 가정을 둔 것입니다. 실제 편입 자산이 아닙니다.
- 예측 모델·성능 지표는 없습니다. 이 단계의 목표는 "담당자가 무엇을 확인해야 하는지 근거를 정리하는 것"입니다.
- 재무제표 **주석**(차입금 만기 구조, 약정 조건)은 아직 도구로 읽지 않습니다. 가장 중요한 공개 자료 중 하나라 다음 확장 과제입니다.
- 시장 신호는 KIS API 가, 재무·공시는 DART 가 주 자료입니다. KIS 는 "시장 반응을 빠르게 보는 눈"으로 쓰였습니다.
- 조직별 담당 범위(심사 vs 사후관리)는 외부에서 확인할 수 없어 "기업금융 투자자산 모니터링 담당자"를 가정했습니다.

## 다음 단계 (면접 전까지)

## 구조

```
monitor/
  kis_client.py    KIS Open API 조회 전용 클라이언트 (토큰 캐시, 호출 제한, 응답 캐시)
  dart_client.py   OpenDART (공시 목록, 단일회사 전체 재무제표, 주요사항보고서, 채무증권 신고서)
  tools.py         도구 4종 — 기준일 필터, 근거 id 부여, 지표 계산
  signals.py       변화 탐지 (상환능력 / 시장 분리)
  agent.py         조사 Agent 루프 (단일 Agent + 도구, 최대 6스텝, trace)
  verify.py        메모 검증 (근거 id · 숫자 · 단정 표현 · 조달 완료 표현)
  report.py        담당자용 마크다운 메모
scripts/           run_monitor · run_case(사례 복기) · baseline(대조군) · build_universe(대상 선정)
tests/             네트워크 없는 도구·검증 테스트
docs/business_notes.md   IMA 사업 공부 노트 (출처·확인 필요 표시)
```
